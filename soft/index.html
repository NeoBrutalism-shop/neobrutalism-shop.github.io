WHY SOFT

Not a theme.
A product language.

Soft keeps the unmistakable physicality of Neo-Brutalism, then disciplines it for dense, long-session software. The result is expressive without becoming exhausting.

01

Physical feedback

Raised controls compress into their shadow. Hover approaches the surface. Press seats the control. Nothing floats upward just because a cursor arrived.

ONE SYSTEM · THREE PATHS

Use the source of truth.
Not a visual imitation.

The framework-agnostic CSS contract is canonical. React wrappers and shadcn registry items stay intentionally thin so no integration can fork Soft’s tokens, themes, or interaction physics.

CSSCanonical

Framework-agnostic CSS

WordPress, Astro, vanilla, PHP, or any frontend that can load CSS.

@import "./src/index.css";
RThin wrapper

React primitives

Native semantics mapped onto stable Soft classes. Styling stays in the shared CSS system.

import { Button } from "@neobrutal/soft-react"
SRegistry

shadcn source registry

A registry base installs the complete system contract before UI primitives.

registry.json → soft-base → soft-button
LLM

BUILT FOR HUMANS + AGENTS

Machine-readable design discipline.

Soft ships `LLMS.md`, `llms.txt`, a registry manifest, semantic component states, and explicit forbidden behaviors. An agent should know not only how a button looks, but why it presses, when an action needs approval, and how partial failure must be represented.

inspect→compose→validate→ship
